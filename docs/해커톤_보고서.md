# 해커톤 보고서

## 작품 주제

### 작품명(가칭)

**한걸음** — 지적·발달장애인의 이해, 일상 수행을 돕는 보호자 연계형 접근성 앱

### 제작 배경(문제 상황)

지적·발달장애인은 인지 능력, 문해력, 정보 처리 속도, 선호하는 의사소통 방식에서 개인차가 크다. 그러나 우편물, 안내문, 복약 안내, 금융 화면 등 일상 정보는 대부분 획일적인 글과 복잡한 절차로 제공된다. 이 때문에 당사자가 정보를 이해하거나 행동으로 옮기는 과정에서 지속적인 타인의 도움이 필요하다.
따라서 개인별 접근성 설정, 단계별 행동 안내, 보호자 연결을 하나의 서비스로 통합할 필요가 있다.

### 솔루션

앱을 보호자 모드와 당사자 모드로 구성한다.

#### 보호자 모드

- **개인별 접근성 설정:** 텍스트 난이도, 픽토그램 사용 여부, 글자 크기, 음성 속도 등을 설정하면 당사자 화면에 자동 반영한다.

#### 당사자 모드

- 초기 화면에는 큰 `카메라 쉬운 말 번역`버튼만 표시한다.
- 문서를 촬영하면 OCR로 글자를 인식하고 개인 수준에 맞는 쉬운 말로 변환한다.
- 쉬운 글, 픽토그램, 느린 TTS를 함께 제공하며 읽고 있는 문장을 실시간으로 강조한다.
- 
### 기대 효과

- **당사자:** 우편물 확인, 약 복용, 장보기 등 일상 과제를 더 독립적으로 수행하여 자립성과 자기효능감을 높인다.
- **보호자:** 원격 설정을 통해 반복적인 밀착 돌봄 부담을 줄이고 심리적 안심을 얻는다.
- **상담·치료:** 단계별 소요 시간과 도움 요청 기록을 행동 변화 및 상담 자료로 활용할 수 있다.

### 유사 제품과 차별점

| 구분 | 주요 기능 | 한계 또는 차별점 |
|---|---|---|
| 온글 | 복잡한 문장을 쉬운 글로 변환 | 행동 수행과 보호자 연계 기능이 제한적 |
| 나의 AAC | 그림 상징을 통한 의사소통 지원 | 일상 절차의 단계별 수행·인증 기능이 제한적 |
| 한걸음 | 개인별 UI, 멀티모달 쉬운 말, 미션 수행, 사진 인증, 보호자 확인 | 정보 제공에서 끝나지 않고 실제 행동 완료까지 연결 |

## 작품 제작

### 작품 설계

#### 설계 개념

1. **개인화:** 장애 유형을 하나의 등급으로 단순화하지 않고 글 난이도, 그림 선호, 음성 속도를 독립적으로 설정한다.
2. **한 화면, 한 행동:** 선택지와 정보를 최소화하여 인지 부담과 오조작을 줄인다.
3. **익숙한 단서:** 일반 이미지보다 보호자가 촬영한 실제 장소·물건 사진과 익숙한 목소리를 우선 사용한다.
4. **사람 중심 안전:** AI는 설명과 위험 신호 탐지를 보조하고, 고위험 금융 판단은 보호자가 최종 확인한다.
5. **실패 허용:** 언제든 도움을 요청하거나 이전 안내를 반복해서 들을 수 있게 한다.

#### 작동 원리

1. 보호자가 당사자의 접근성 프로필을 설정한다.
2. 설정값이 서버에 저장되고 당사자 앱의 글자, 문장, 그림, 음성 UI에 반영된다.
3. 쉬운 말 기능은 촬영 이미지에서 OCR로 텍스트를 추출한 뒤 쉬운 문장으로 변환한다.
4. 변환 결과는 원문 핵심 정보와 대조하고, 확신도가 낮거나 날짜·금액·계좌 등 중요 정보가 있으면 보호자 확인 표시를 추가한다.
5. 미션은 보호자가 만든 단계, 사진, 음성, 예약 시간으로 구성된다. 당사자 앱은 한 번에 한 단계만 보여준다.
6. 사진 인증 후 완료 시간과 도움 요청 여부를 기록하고 다음 단계로 이동한다.
7. 금융 안전 MVP는 실제 송금을 직접 제어하지 않고, 시연용 금융 화면에서 보호자 승인 요청과 대기·차단 흐름을 검증한다.

#### 외·내적 설계

- **당사자 화면:** 고대비 색상, 큰 터치 영역, 짧은 문장, 고정된 SOS 위치, 불필요한 메뉴 제거
- **보호자 화면:** 프로필 설정, 미션 편집, 승인 요청, 활동 리포트를 탭으로 구분
- **앱 계층:** 보호자 앱과 당사자 앱이 인증·프로필·미션·알림·리포트 API를 통해 서버와 통신
- **처리 계층:** OCR, 쉬운 말 변환, 픽토그램 매칭, TTS를 분리해 오류 발생 시 보호자가 결과를 확인 가능
- **데이터 계층:** 계정, 접근성 프로필, 미션, 수행 기록, 승인 요청을 권한별로 분리 저장

### 제작 일정

| 단계 | 주요 작업 | 산출물 |
|---|---|---|
| 1. 기획 | 사용자 시나리오, 요구사항, MVP 확정 | 기능명세서, 화면 흐름 |
| 2. 설계 | UI 와이어프레임, 데이터·API 설계 | 프로토타입, 시스템 설계 |
| 3. 핵심 개발 | 프로필, 쉬운 말, 미션 수행 구현 | 당사자·보호자 앱 MVP |
| 4. 연동 | 알림, 사진 인증, 리포트, 승인 시연 | 통합 빌드 |
| 5. 테스트 | 사용성, 접근성, 오류·안전 테스트 | 테스트 기록, 개선 목록 |
| 6. 발표 | 시연 시나리오, 보고서, 발표자료 정리 | 최종 제출물 |

> 실제 해커톤 기간이 확정되면 단계별 날짜와 담당자를 추가한다.

## 작품 테스트

### 테스트 목적

- 당사자가 최소한의 도움으로 핵심 과제를 완료할 수 있는지 확인한다.
- 개인별 UI 설정이 실제 사용성과 이해도를 개선하는지 확인한다.
- AI 오류나 네트워크 장애가 위험한 금융 승인으로 이어지지 않는지 확인한다.
- 보호자가 미션과 활동 기록을 쉽게 관리할 수 있는지 확인한다.

### 테스트 방법

- **주체:** 개발팀이 기능 테스트를 수행하고, 접근성 전문가 또는 보호자 자문을 받아 사용성 시나리오를 검토한다.
- **대상:** 초기에는 비장애 성인과 보호자 역할 참가자로 안전한 모의 테스트를 진행한다. 실제 지적·발달장애인 테스트는 충분한 설명, 당사자·법정대리인 동의, 전문가 입회, 중단 권리를 보장한 후 진행한다.
- **과제:** 안내문 쉬운 말 확인, 약 복용 미션, 장보기 미션, SOS 요청, 모의 금융 승인·차단을 수행한다.
- **도구:** 화면 녹화, 수행 시간 측정, 관찰 기록지, 5점 사용성 설문, 오류 로그를 사용한다.
- **측정값:** 과제 성공률, 단계별 소요 시간, 오조작 수, 도움 요청 수, 쉬운 말 핵심정보 보존율, 승인 알림 도착 시간, 잘못된 금융 허용 건수

### 결과 분석

테스트 후 예상 목표와 실제 측정값의 차이를 분석한다. 성공률이 낮은 단계는 문장 길이, 버튼 수, 사진의 익숙함, 음성 속도별로 원인을 구분한다. 쉬운 말 결과는 원문의 날짜·장소·금액·행동 지시가 유지되었는지 별도로 평가한다. 금융 테스트에서는 평균 응답 시간보다 잘못된 허용 여부를 최우선 안전 지표로 사용한다.

## 해석 및 결론

### 결론

현재 단계에서는 설계와 MVP 목표가 수립되었으며 실용성은 테스트 후 확정해야 한다. 본 작품은 쉬운 정보 제공뿐 아니라 개인별 접근성 설정, 단계별 행동 유도, 사진 인증, 보호자 연결을 하나의 흐름으로 제공한다는 점에서 기존 단일 기능 서비스와 구별된다. 특히 AI가 금융 거래를 독자적으로 승인하지 않고 보호자가 최종 판단하도록 설계하여 오류로 인한 피해 가능성을 줄인다.

### 추후 개선사항

- 실제 사용자 테스트를 통한 인지 수준별 문장·화면 기준 세분화
- 쉬운 말 변환 결과의 핵심정보 자동 대조 및 보호자 검수 기능 강화
- 오프라인 음성 안내와 네트워크 장애 대응
- 금융기관·운영체제 정책을 검토한 정식 승인 연동 가능성 조사
- 사진과 음성의 암호화, 보관 기간 설정, 삭제 기능 강화
- 치료사·복지사와 공유할 수 있는 동의 기반 리포트 기능 검토
