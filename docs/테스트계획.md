# 테스트 계획

## 원칙

- 기능 정확성보다 사용자 안전을 우선한다.
- 실제 당사자를 대상으로 할 경우 쉬운 설명과 자발적 동의, 중단 권리, 개인정보 최소 수집을 보장한다.
- 금융·복약 테스트에는 실제 계좌, 실제 송금, 실제 약을 사용하지 않는다.

## 테스트 항목

| ID | 테스트 | 방법 | 합격 기준 |
|---|---|---|---|
| T-01 | 접근성 설정 반영 | 설정값별 화면·음성 비교 | 모든 설정이 재실행 후에도 유지 |
| T-02 | OCR 인식 | 난이도가 다른 안내문 촬영 | 핵심정보 인식률 95% 이상 |
| T-03 | 쉬운 말 보존 | 날짜·금액·행동 지시 대조 | 핵심정보 보존율 95% 이상 |
| T-04 | 미션 완수 | 3~5단계 모의 과제 수행 | 참가자의 80% 이상 완료 |
| T-05 | 사진 인증 | 정상·흐림·무관 사진 입력 | 오류 시 재촬영 안내 제공 |
| T-06 | SOS | 각 미션 단계에서 요청 | 보호자 알림 및 상태 기록 성공 |
| T-07 | 승인·차단 | 모의 금융 요청 수행 | 승인 전 진행 0건, 위험 오승인 0건 |
| T-08 | 장애 대응 | 네트워크·AI 응답 차단 | 자동 승인 없이 쉬운 오류 안내 |

## 진행 절차

1. 테스트 목적과 중단 방법을 설명하고 동의를 확인한다.
2. 연습 과제로 버튼과 음성 안내를 익히게 한다.
3. 진행자는 정답을 유도하지 않고 관찰한다.
4. 성공 여부, 시간, 오조작, 도움 요청을 기록한다.
5. 짧은 5점 척도와 쉬운 질문으로 만족도를 조사한다.
6. 개인정보가 포함된 화면 녹화와 사진은 식별 코드를 사용하고 정해진 기간 후 삭제한다.

## 분석 방법

- 예상 목표와 실제 평균·중앙값·범위를 비교한다.
- 글 난이도와 픽토그램 설정별 성공률을 분리한다.
- 실패 원인을 문장 이해, 버튼 인지, 사진 이해, 시스템 오류로 분류한다.
- 표본이 작을 때 통계적 일반화를 피하고 관찰된 경향으로만 기술한다.
